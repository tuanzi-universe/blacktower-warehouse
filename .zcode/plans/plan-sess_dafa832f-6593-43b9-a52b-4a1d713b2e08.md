# 仓库分区改造计划

## 背景

- 现布局 8 区 × 2 侧 × 55 格 = 880 格，实际占用 517 格；`partition.csv` 的 R 侧每行重复两次（1320 行），B-R 还是反序。
- 旧分区职能：A 原料、B 建材、C 红石、D 装备、E 色彩、F 植物农业、G 生物资源、H 地形。
- 现有 `itemsorter-points.json` 是旧物品名迁移来的 489 条规则，未覆盖新物品、附魔书和药水。
- 目标：不沿用当前新分区，以旧分区职能和“内侧高频”规律为骨架重建单元表，覆盖 `items.json` 全部生存可获取物品，输出符合 `itemsorter-points-spec.md` 的点位 JSON，并让 `partition-2d.html` 只保留新分区、通过 fetch 渲染。

## 已确认的落位规则

1. **门、栅栏、链、火把 → B-R**（建材库右列，现铜门/铜链/火把所在侧）。
2. **木材拆分**：
   - A-R：每个树种 1 格，含原木、去皮原木/木、木板、树苗、树叶（绯红/诡异菌柄用菌菇作“树苗”）。
   - B-R：同树种另 1 格，含台阶、楼梯、门、活板门、栅栏、栅栏门、告示牌、悬挂告示牌、按钮、压力板、船/运输船、展示架、竹马赛克。
   - 盆栽不在 `items.json`，视为对应树苗副产品，不单独建单元。
3. **D-L 修正为纯附魔区**：43 个附魔各 1 格（按等级拆规则），第 44 格“其他附魔书”兜底；D-R 全部放装备/武器。
4. **药水放 H-R 整列**：H-L 放地形，H-R 44 格 = 40 个效果各 1 格 + 普通/喷溅/滞留 3 个形态兜底 + 1 格药水箭，剩余 11 格备用。
5. **只生成到 `warehouse-partition`**，不改 `warehouse-bot/config/itemsorter-points.json`。

## 生成器设计

新增 `tools/build.js`、`tools/families.js`、`tools/validate.js`。

1. **解析 `partition.csv`**
   - 按 `area+side+block_x/block_z` 去重，得到 880 个唯一格。
   - 几何排序：A/E 按 z 递减，B/C/D 按 x 递增，F/G/H 按 x 递减。
   - 点位换算沿用现网规律：`x=bot_x+0.5, y=bot_y, z=bot_z+0.5, yaw=bot_face_yaw, pitch=0`。

2. **物品全集**
   - `items.json` 1658 项，排除 110 项生存不可获取：
     - 空气 1；刷怪蛋 88；
     - 命令方块 4、屏障、光源、结构方块/结构空位、拼图、基岩、末地传送门框架、强化深板岩、紫水晶母岩、石化橡木台阶、试炼刷怪笼、宝库、测试方块 2、玩家头颅、知识之书、调试棒。
   - 剩余 1548 项，每一项必须且只能落入一个单元。

3. **单元表**
   - `families.js` 维护约 570–620 个单元：`unit_id, area, side, group_cn, unit_cn, entry_type, rep, matcher`。
   - matcher 支持精确 ID、前缀/后缀、正则和手工覆盖；规则按“具体→通用”顺序匹配。
   - 变体合并：树种、16 色、石/深板岩/铜氧化、工具按类型、护甲按部位、珊瑚活/死、生熟肉按动物、唱片/陶片/模板等按类。
   - 未匹配清单必须为 0；同时检查同一物品被多个单元命中。

4. **点位 JSON**
   - 每个可获取物品 1 条 `{match:{name:"minecraft:<id>"}, point}`；全部同单元共享同一 point，机器人到点一次投掷整族。
   - 不使用 `nameRegex`，全部精确 `name`，避免正则与前缀问题。
   - 附魔书：43 个附魔 × 1..maxLevel 的精确等级规则 + 1 条通用 `enchanted_book` 兜底；顺序按“经验修补→耐久→效率→时运→精准采集→战斗→防护→诅咒”，多附魔书落到首个命中单元。
   - 药水：40 个效果 × 普通/喷溅/滞留 = 120 条 `{name:"minecraft:potion|splash_potion|lingering_potion", effects:[<数字效果ID>]}`，效果 ID 用 26.1 注册表 0–39；随后 3 条形态兜底；`tipped_arrow` 1 条药水箭。
   - 规则顺序即优先级，不写 `weight`；特殊规则全部排在通用兜底之前。
   - 特殊点位沿用现网：`trash/collector/minecart/button/ready/readyButton` 原值；`homeMode=teleport` 不输出 `home`。
   - 输出 UTF-8 无 BOM、2 空格缩进、先写临时文件再原子替换。

5. **审计文件**
   - `partition_new.csv`：880 行全量布局（含空位、单元、代表物、坐标、yaw）。
   - `item_map.csv`：1548 行逐物品映射。
   - `storage_units.csv`：全部单元及点位。
   - `分区方案.md`：按现有风格改成短表格，更新现状、分区表、合并规则、附魔/药水、排除项、文件说明。

## HTML 改造

保留现有 CSS/布局，重写数据与渲染：

- 删除“现状/新分区”切换、“叠加现状”；页面只显示新分区。
- `fetch('itemsorter-points.json')` 拉取规则，按 point 的 `x/y/z/yaw/pitch` 分组成存储单元；point.label 为单元名，首条规则 name 决定材质，规则数即变体数。
- 内嵌 880 格几何数组（area/side/序号/方块坐标/点位坐标/yaw）、材质表和物品中文名表；所有物品/单元/点位信息来自 fetch。
- 保留：缩放/拖动、显示材质、隐藏空位、清除选择；新增“显示站位点”（在 bot 站位画点和朝向）。
- 侧栏按区→侧→组列出单元、格号、变体数；点选高亮，tooltip 显示单元名、坐标、代表物、变体列表。
- fetch 失败（file:// 打开）显示横幅，提示 `python -m http.server`，不内嵌兜底数据。

## 验证

1. `node tools/build.js`：0 未匹配、1548/1548、每侧 ≤55、单元 ≤880。
2. JSON 校验：`JSON.parse` 成功、无 BOM、根为 object、无未知字段；用 bot 的 `loadItemSorterPoints`（tsx）真实加载一次。
3. 语义校验：无重复 match、无通用规则遮蔽特例、`button` 与 collector 水平 ≤3/垂直 ≤2、ready 与 readyButton ≤4.5。
4. 匹配冒烟：普通物品按 name、附魔书按 stored_enchantments 等级、药水按 effects 数字 ID，抽查每个区若干条。
5. 浏览器验证：本地 HTTP 服务 + Playwright 打开 `partition-2d.html`，确认 fetch 成功、880 格渲染、区计数正确、材质/空位/站位点开关正常、无 console 错误。

## 已知限制

- 标准药水若只有 `potionId`、无 `customEffects`，运行时无法按效果拆分，会落到 3 个形态兜底格；按效果分格对自定义效果药水生效。
- 多附魔书按规则顺序落到首个命中附魔格，不复制到多个格。
- `potted_*`、`*_wall_fan`、`twisted_vines_plant` 不在 `items.json`，不生成规则。
- 未映射物品（含被排除的生存不可获取项）由 `trash` 兜底。
