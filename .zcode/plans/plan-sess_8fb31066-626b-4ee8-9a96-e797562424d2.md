# 仓库分区点位：Excel / JSON 导入导出

## 1. 背景与已确认决策

当前 `partition-2d.html` 只读：从 `itemsorter-points-v1.json` / `itemsorter-points-v2.json` fetch 数据并渲染，没有编辑或导出入口。本次新增：

- 导出 Excel：A–H 每个分区一个 sheet，另加“汇总”和“规则明细”两个参考 sheet。
- 导出 JSON：v2 → `itemsorter-points.json`；v1 → `itemsorter-points-v1.json`。
- 导入 Excel / JSON：整份替换 v2 工作版本，v1 保持冻结。
- 入口：工具栏单个“数据”按钮 + 弹窗（已确认）。
- Excel 结构：单元级主表 + 规则明细参考表（已确认）。
- 导入生效：内存 + localStorage 暂存，刷新保留，可“恢复磁盘 v2”（已确认）。
- 导出范围：当前显示版本（已确认）。
- 导入错误：严格整份拒绝，当前数据不变，列出 sheet/行/字段（已确认）。

## 3. Excel 工作簿格式

### 3.1 Sheet 顺序

`汇总` → `A` → `B` → `C` → `D` → `E` → `F` → `G` → `H` → `规则明细`。
若导入数据含 A–H 之外的 area，额外生成 `其他` sheet（带 `区` 列）。

### 3.2 分区 sheet（A–H）

每区固定 110 行数据：L 1–55、R 1–55，空位也保留。第 1 行为表头：

`区 | 顺序 | 侧 | 格位 | 单元名 | 类型 | 代表物 | 合并物品 | 规则数 | 规则(JSON) | 自定义点位(JSON) | 备注`

- `区`：A–H，与 sheet 名一致，导入时校验。
- `顺序`：该单元第一条规则在原 JSON 中的 1-based 序号，用于导入时恢复规则优先级；留空则按 sheet/格位顺序追加。
- `侧` / `格位`：L/R、1–55；定位以这两个字段为准。
- `单元名`：对应 `point.label`；空位行留空。
- `类型` / `代表物` / `合并物品` / `规则数` / `备注`：人读列，导入忽略。
- `规则(JSON)`：该单元全部规则的紧凑 JSON 数组，元素为 `{match, weight?}`；顺序即单元内优先级。导出不含 `point`。
- `自定义点位(JSON)`：仅当 `格位` 留空时使用，格式 `{x,y,z,yaw,pitch}`；与 `格位` 同时填写视为错误。

格位坐标推导：`x=bot_x+0.5`、`y=bot_y`、`z=bot_z+0.5`、`yaw`、`pitch`，直接使用注入页面的 880 格几何数据。当前所有 v1/v2 单元都落在格位上，因此分区 sheet 无自定义点位行。

编辑方式：
- 移动单元：整行剪切到目标空位行，或改 `侧`/`格位`（改后行可能不再按格位排序，导入仍按字段值处理）。
- 新增单元：在空位行填 `单元名` + `规则(JSON)`。
- 删除单元：清空该行 `单元名` 和 `规则(JSON)`。
- 改规则：编辑 `规则(JSON)`；`规则明细` 仅供审阅，不参与导入。

### 3.3 汇总 sheet

- 元数据：版本、导出时间、数据源、规则数、单元数、占用/空余格。
- 特殊点位表：`键 | 中文名 | x | y | z | yaw | pitch | label`，覆盖 `home`、`trash`、`collector`、`minecart`、`button`、`ready`、`readyButton`。
  - `button` / `readyButton` 的 yaw/pitch 留空。
  - `ready` 的 yaw/pitch 可留空（按规范缺省 0）。
- 分区统计表：`区 | 方位 | 主题 | L 单元 | R 单元 | 占用格 | 空余格 | 规则数`。
- 编辑说明：格位定位、JSON 规则、空位行、导入整份替换等。

导入时只读取特殊点位表；统计与说明仅人读。`collector`、`minecart` 缺失为错误；`trash`、`button`、`ready`/`readyButton` 缺失为警告。

### 3.4 规则明细 sheet

每条规则一行，按原 JSON 顺序：

`全局序号 | 区 | 侧 | 格位 | 单元名 | 规则序号 | 权重 | 物品ID | 物品ID正则 | 附魔(JSON) | 自定义名称 | 自定义名称正则 | Lore | Lore正则 | 药水ID | 效果(JSON) | x | y | z | yaw | pitch`

首行加提示“仅供审阅，导入以各分区 sheet 的规则(JSON) 为准”。导入完全忽略此 sheet。

## 4. JSON 导入导出

### 4.1 导出

- 当前 v2：文件名 `itemsorter-points.json`；当前 v1：`itemsorter-points-v1.json`。
- UTF-8 无 BOM、2 空格缩进、末尾换行。
- 按规范字段顺序重建：`items, home?, trash?, collector, minecart, button?, ready?, readyButton?`；未知字段拒绝，不静默丢字段。
- `Point` 保留 `label/area/side`（存在时）；`ReadyPoint` 保留可选 `yaw/pitch/label`；`BlockPoint` 只保留 `x/y/z/label`。
- 导出前执行完整校验；当前数据应原样回导（v1/v2 均 1830 规则、575 单元）。

### 4.2 导入

- `.json`：`File.text()` 读取，去 BOM（有 BOM 时给警告），`JSON.parse` 后走完整校验。
- 导入成功后整份替换 v2，并自动切换到 v2 视图；v1 不变。
- 导入失败不修改当前 `versionData` / localStorage。

## 5. 校验规则（严格导入）

错误（任一存在即整份拒绝）：
- JSON 语法、根不是 object、`items` 不是数组。
- 根/规则/match/point 出现未知字段。
- `collector` / `minecart` 缺失或字段非法。
- `match` 为空；`name`/`nameRegex`、`customName`/`customNameRegex`、`lore`/`loreRegex` 同时出现。
- `enchantments` 非空对象、值为 ≥1 整数；`effects` 非空数组、元素为字符串或 ≥0 整数；`potionId` 为 ≥0 整数。
- `weight` 非整数；正则无法编译。
- 规则点位缺 `x/y/z/yaw/pitch` 或非有限数字。
- 完全重复的 `match`（键排序后比较）。
- 同一点位对应多个不同单元名；同一格位对应多个单元。
- Excel：缺 A–H sheet、缺“汇总”特殊点位表、表头缺失、`区` 与 sheet 不符、`规则(JSON)` 解析失败、`格位` 与 `自定义点位` 同时填写/都为空、格位重复、空单元名但有规则、有单元名但规则为空。

警告（允许导入，页面列出）：
- 缺少 `trash`、`button`、`ready`/`readyButton`；`home` 不警告（当前数据无 home）。
- `button` 与 `collector` 水平 >3 或垂直 >2；`ready` 与 `readyButton` >4.5 格。
- 规则点位不在 880 格内（无法在图上显示）、`area/side` 与格位不一致。
- 单元名重复、area 不在 A–H、`items` 为空。
- `name` 非小写、`nameRegex` 不含 `minecraft:`、正则带 `/.../`、无 `name`/`nameRegex` 的宽泛规则、同名通用规则可能遮蔽特例。
- Excel 中 `版本` 为 v1（仍作为 v2 导入）。

Excel 校验错误定位到 `sheet + Excel 行号`，JSON 定位到 `items[n].match.x` 路径；最多展示 200 条，支持复制错误清单。

## 6. 页面交互与状态

### 6.1 入口

工具栏新增 `数据` 按钮，打开弹窗：
- `导出 Excel`、`导出 JSON`、`导入 Excel / JSON`。
- 数据源状态：`v2 · 磁盘 itemsorter-points-v2.json` 或 `v2 · 已导入 xxx.xlsx（时间）`。
- `恢复磁盘 v2`（有导入缓存时）／`重新读取 v2`；操作前确认。
- 说明：导入只更新本页 v2；写入 bot 需导出 JSON 后替换 `config/itemsorter-points.json`。

移动端：弹窗全屏化、按钮单列、错误列表可滚动；z-index 高于搜索层和底部面板；Esc/点击遮罩关闭。

### 6.2 导入/导出流程

- 导出：同步使用已加载的 `XLSX`，生成 Blob 下载；按钮显示“处理中…”，成功后 toast 文件名。
- 导入：文件选择器接受 `.json/.xlsx/.xls`，限制 20 MB；Excel 解析与校验在内存完成，成功后才替换数据。
- 已有导入数据时再次导入，先确认“将覆盖当前导入数据”。
- 成功后：关闭弹窗或展示成功摘要（有警告时留在弹窗列出警告）；重绘地图、搜索、侧栏、v1 差异。
- 失败：弹窗内红字错误清单，当前数据不变。
- 选中单元按 label 尽量保留；找不到则回到概览。

### 6.3 缓存与版本

- localStorage key：`warehouse-partition.imported-v2.v1`，存 `{schema:1, importedAt, fileName, source, data}`。
- 启动时读取缓存并通过校验则直接作为 v2；`sub` 显示 `· 已导入`。
- `fetchVersion('v2')` 在存在导入缓存时返回缓存；`恢复磁盘 v2` 清除缓存并强制 fetch。
- 配额不足时降级为仅本次会话，并提示。
- 导入始终替换 v2；切回 v2 时使用缓存数据，不重新 fetch 磁盘。
- `specialPoints` 增加 `home`（存在时），概览侧栏展示；地图不绘制 home。

### 6.4 兼容性修正

- `computeUnits` 在 `point.area/side` 缺失时用 x/z 查 880 格回填显示用 area/side/slot（不改原始 JSON）。
- `renderArea` / `renderUnit` 对 `slot` 为空的自定义点位显示 `—`，避免出现 “null”。
- 数据弹窗打开时忽略地图缩放快捷键。

## 9. 注意事项

- `规则明细` 是只读参考，导入不会读取；改规则请改分区 sheet 的 `规则(JSON)`。
- `顺序` 用于保持优先级；移动单元后它不会自动跟随格位，留空则按 sheet/格位顺序。
- 当前数据唯一一个跨单元规则不连续的单元是“药水·袭击之兆”，按单元聚合后规则会相邻；其匹配目标与其他药水单元互斥，行为不变，测试中会核对单元 match 集合。
- 导入只改浏览器 v2，不直接写 bot 配置；v1 始终冻结。
- SheetJS 本地加载，不依赖 CDN；无网络也可用。
