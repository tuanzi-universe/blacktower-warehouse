## 3. 归位规则

1. 一单元 = 一族；同族变体生成多条 `name` 规则，共享同一 `point`。
2. 热物品优先靠内：A-L 1–25 矿物、C-L 1–21 红石、E-L/E-R 药水（含玻璃瓶）、G 全区，全部从 slot 1 起排。
3. E 区自然方块整并入 H 区（合并区）：原 E-L 26 格原序迁 H-L，黏土球插黏土后（H-L 10）、燧石插沙砾后（H-L 15），雪球保持雪块后（H-L 21）；海绵含湿海绵合 1 格、苔藓/苍白苔藓各含覆地苔藓合 1 格（H-L 自然段 25 格）；原 E-R 33 格原序迁 H-R 主段，磨制 10 格拆单紧跟本体，海晶灯并入光源段，平滑石头抽出单格置于圆石后（H-R 3）。
4. A-R 木材 26 格 + 木棍 27（合成原材仅剩木棍；树脂迁 H-L 树脂块旁，纸/书迁 D-R 书架旁）。
5. 燧石/黏土球/红砖/下界砖迁出 A 区：前两者按亲缘入 H-L（沙砾后/黏土后），红砖/下界砖入 H-L 基础方块段（红砖块/下界砖块旁，H-L 26/27、30/31）；石英块自 H-L 迁回 A 区石英后（A-L 30，按 A 区 原矿→单质→块 逻辑）。

## 12. 黑名单

- `blacklist` 为 `Match[]`，任意一条命中即视为黑名单；非空时必须同时有 `trash`。
- v1/v2/v3 未提供 `blacklist` 时默认 `minecraft:wooden_hoe`；显式 `[]` 表示禁用。
- 查看器：概览显示黑名单条目与“编辑黑名单”；数据弹窗支持每行一个物品 ID 或 Match JSON 数组，应用/取消/还原。
- 修改按版本独立暂存，版本标签显示 `*`，`sub` 与数据源显示“黑名单已修改”；导出 JSON 保存，`重新读取 v3` 会先确认再丢弃 v3 修改。
- 导入视图的黑名单单独保存在导入缓存；“还原导入值”回到导入文件的值。
- Excel 导出新增「黑名单」sheet（每行一条 Match）；导入缺该 sheet 时补默认值，sheet 存在但为空则清空。
- JSON 导出/导入根节点含 `blacklist`；导入缺省时同样补 `minecraft:wooden_hoe`。

## 13. 导入导出格式

- JSON 根字段：`items`、`blacklist`、`home?`、`trash?`、`base`、`minecart?`、`button?`、`ready?`、`readyButton?`；未知字段拒绝。
- `base` 必填站位点（x/y/z/yaw/pitch）；`trash`/`minecart` 仅 `yaw`/`pitch`；`button`/`readyButton` 为方块坐标；`ready` 的 yaw/pitch 可省略。
- 规则为 `{ weight?, match, point }`；`match` 支持 name/nameRegex/enchantments/customName/customNameRegex/lore/loreRegex/potionId/effects，互斥字段不能同时出现。
- Excel：A–H 每区一个 sheet（单元 + `规则(JSON)` + `自定义点位(JSON)`），「黑名单」每行一条 Match；「汇总」特殊点位表中 `trash`/`minecart` 只填 yaw/pitch。导入 v1/v2 旧 `collector` 格式时自动迁移为 `base` 与新投掷方向。
